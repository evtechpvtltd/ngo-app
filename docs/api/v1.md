# API v1 Contract

Every field below is required documentation for a new endpoint per
`app.md #6`. This file documents what actually exists; add a new section
here in the same PR that adds the route, not after.

---

## `GET /api/v1/health`

| | |
|---|---|
| **Authentication** | None |
| **Authorization** | None (public) |
| **Request schema** | No body/params |
| **Response schema** | `{ status: "ok", version: string }` |
| **Rate-limit class** | Unrestricted (liveness probe) |
| **Audit** | Not audited |
| **Idempotency** | N/A (GET, no side effects) |
| **Offline behavior** | Not applicable — used by uptime monitors, not the app UI |
| **Cache behavior** | Service worker: network-only (falls under the blanket `/api/*` fallthrough in `service-worker/sw.ts`) |
| **Errors** | Never returns an error response in v0.0.1 |

## `GET /api/v1/system/version`

| | |
|---|---|
| **Authentication** | None |
| **Authorization** | None (public — `app_versions_select_public` RLS policy) |
| **Request schema** | No body/params |
| **Response schema** | `{ version: string, build_id: string, minimum_supported_version: string, update_type: "none" \| "optional" \| "recommended" \| "required" }` |
| **Rate-limit class** | Unrestricted (read-only, cheap) |
| **Audit** | Not audited |
| **Idempotency** | N/A (GET, no side effects) |
| **Offline behavior** | Drives the update banner (`components/native/update-banner.tsx`) indirectly via the service-worker update lifecycle, not by polling this endpoint directly in v0.0.1 |
| **Cache behavior** | Service worker: network-only |
| **Errors** | `INTERNAL_ERROR` (500) if `public.app_versions` is unreachable — the DB error is logged server-side, never returned in the response body |

---

No mutating (`POST`/`PATCH`/`DELETE`) endpoints exist in v0.0.1. The first
one to be added (likely under `/api/v1/profile` or `/api/v1/reviews`) must
fill in every row above, including a real rate-limit class and audit
requirement, before merging.
